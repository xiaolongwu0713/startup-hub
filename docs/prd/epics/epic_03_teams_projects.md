# epic-03-teams-projects — 认领/组队与推进（看板、里程碑、成果）

> 约束回顾：聚焦中国大陆中文用户；“创业点子”为可认领/加入的微项目想法（非临时工作）；MVP ≤ 6 个月、预算 ≤ ¥1000；短期北极星：日活发帖量（DAU Post）。

## 1. 目标
- 将“点子”变为**可推进的小项目**：认领角色、成团协作、里程碑提交**成果凭证**，沉淀到个人/团队作品集。

## 2. 用户故事
1. 作为参与者，我能对感兴趣的点子**申请认领某个角色位**，并附简短自荐。
2. 作为发起人，我能**管理角色位**（通过/拒绝、替换），并一键**开启项目看板**。
3. 作为团队成员，我能在**简易看板**推进任务，提交里程碑的**Demo/截图/链接**，并获得通过/打回反馈。
4. 作为任何用户，我能在**作品集**中查看某人/团队做成过什么。

## 3. 功能需求
### 3.1 角色位/认领
- 角色预设（产品/设计/开发/运营/BD…），可设置人数上限。
- 认领申请（自荐语 + 过往凭证链接）；发起人审批。

### 3.2 项目看板
- 列：Todo / Doing / Done；任务卡片（标题、描述、指派人、截止、评论、附件）。
- 任务变更通知；最小的活动记录。

### 3.3 里程碑与成果凭证
- 里程碑状态：待提交/审核中/通过/打回；提交内容：文本 + 链接/图片/GIF。
- 通过后自动计入**点子进度**与个人**作品集**。

### 3.4 作品集页
- 个人/团队汇总：近 90 天里程碑缩略、点子标签、角色参与记录。

### 3.5 埋点
- `claim_request_submitted/approved`、`kanban_card_move`、`milestone_submitted/approved`、`portfolio_view`。

## 4. 非功能
- **简洁优先**：单项目 ≤ 10 个任务、≤ 3 个里程碑为最佳实践。
- **易用性**：拖拽/长按移动卡片；移动端单列视图。
- **稳定性**：看板与里程碑提交**离线草稿**（网络波动不丢）。

## 5. 验收标准
- 点子被认领率 ≥ 40%。
- ≥ 30% 的点子在 2 周内出现**首个里程碑提交**。
- 作品集页用户周均浏览 ≥ 1.5 次。

## 6. 依赖与风险
- **依赖**：账户系统、通知中心、对象存储（图片/GIF）、轻量文件（链接优先）。
- **风险**：协作复杂度上升（控制在轻看板）；文件审核带来延迟（见审核 epic）。
